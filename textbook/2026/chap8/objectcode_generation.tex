\chapter{目的コード生成}

３番地コードとして生成された命令列は３番地コードを解釈する実行系で実行可能である．
３番地コードは計算機のアーキテクチャからは独立した命令であり，変数はメモリ上にあると
して実行される．コンパイラにおける目的コード生成は，中間コードに対応する目的
計算機の命令語を選択する．ここで，現在の計算機の多くのアーキテクチャでは，メモリにある
データを演算器のレジスタにロードして演算を行い，レジスタに得られた結果をメモリに
書き戻す動作をする．演算器のレジスタとメモリの間のデータの交換速度は一般に計算機の
演算に比べて遅いため，プログラムの解析によってレジスタとメモリの間のデータ交換が
できるだけ少なくなるような目的コードを生成することが望ましい．中間コードの変数の数に
比べてレジスタの数は非常に少ないため，実行プログラムにおいてその時点で頻繁に演算に
用いられる変数をレジスタに置くようなコードを生成することによって実行速度の大幅な
改善が可能になる．変数とレジスタの対応を決定することをレジスタ割当という．

一般にプログラムに対して最適なレジスタ割当を行うことは難しく，３番地コードのフローグラフが
与えられている時に割当アルゴリズムがNP完全な問題である\cite{DBLP:journals/cl/ChaitinACCHM81}ため，
目的コード生成での
レジスタ割当は最適性を保証することは困難である．従って，目的コード生成では，部分的な
プログラムに対して必要なレジスタ数を見積もり，近似的に効率のよい割当手法を与える．
具体的には，３番地コードやSSA形式における変数のデータフローからライフサイクル（生存期間）を解析して，
変数からレジスタへの割当を決定する．

目的コードの命令の選択については目的マシンのアーキテクチャに応じてできるだけサイクル数の
少ない命令（軽い命令）を選択するために命令のコストを見積もるなどの手法がある．しかし，
実際の計算機ではハードウェアによる並列的な実行などの効果や実行ユニットの数などに依存する
ことから，実際的な計算機に対するコード生成の系統的なモデル化は教科書的内容の範囲を越えるため，
本書では扱わない．

\section{算術式のコード生成}

ここでは，算術式に対するコード生成において必要なレジスタの数を見積もる手法を示す．
簡単化のため，以下の範囲に限定する．
\begin{itemize}
    \item 演算子は四則演算($\ttpl$, $\ttsb$, $\ttmu$, $\ttdv$)に限定する．
    \item 命令はメモリ転送命令($\texttt{Load}\ r,e$)と演算命令($\theta\ r,e$)とする．\\
          メモリ転送命令$\texttt{Load}\ r,e$は，$e$で示されるメモリの内容をレジスタ$r$に転送する．
          演算命令$\theta\ r,e$は，$e$で示されるメモリ（またはレジスタ）の内容をフェッチして$r$と$\theta\in\{\ttpl,\ttsb,\ttmu,\ttdv\}$
          で定められた演算を行い，結果を$r$に格納する．
\end{itemize}

例えば，算術式$A\ttpl B\ttsb C$のコードは以下のようになる．

\end{tabular}

とすればよいので必要なレジスタは１つである．これは，$\ttsb$が可換でなく，$\ttmu$が可換であるため２番目の項をまず評価して１番目の項を適用することができるためである．算術式を表す抽象構文木$T$に対して，その計算に必要なレジスタ数を$RN(T)$と書く．
$RN(T)$はアルゴリズム\ref{alg:regNum}で求められる．

\begin{algorithm}
    \caption{$RN(T)$の計算}\label{alg:regNum}
    \begin{algorithmic}
        \Procedure{$RN$}{$T$}
        \If{$\mathsf{isleaf}(T)$}
        \Return 0 \Comment{$T$が葉}
        \Else
        \State $T_1=\mathsf{Left}(T)$ \Comment{$T_1$は左部分木}
        \State $T_2=\mathsf{Right}(T)$ \Comment{$T_2$は右部分木}
        \If{$RN(T_1)=0$ かつ $RN(T_2)=0$}
        \Return 1 \Comment{左右とも葉なのでレジスタ１つ}
        \Else
        \If{$RN(T_1)=0$ かつ $RN(T_2)>0$}
        \If{$\mathsf{root}(T)$が可換演算子}\
        \Return $RN(T_2)$ \Comment{後ろから適用する}
        \Else\
        \Return $\mathsf{max}(2,RN(T_2))$ \Comment{最大２つ必要}
        \EndIf
        \Else
        \If{$RN(T_1)>0$}
        \If{$RN(T_1)=RN(T_2)$}\
        \Return $RN(T_1)+1$
        \Else\
        \Return $\mathsf{max}(RN(T_1),RN(T_2))$
        \EndIf
        \EndIf
        \EndIf
        \EndIf
        \EndIf
        \EndProcedure
    \end{algorithmic}
\end{algorithm}

このレジスタ数の見積もり解析に応じて，使用するレジスタが実際に利用できるレジスタ数の範囲内であれば，レジスタを利用する目的コードを生成できる．しかし，レジスタ数が足りない場合は，レジスタ溢れ(spill)が発生する．このような場合は，フロー解析などの手法を使って最も後で使われる変数をレジスタに割り当てるなどの方法によって効率的に実行する目的コードを生成する．

\section{グラフ彩色によるレジスタ割当}

３番地コードの基本ブロックに対して計算に用いられる変数をできる限り多くレジスタに割り当てる方法について紹介する．基本的なアイデアとして変数の生存期間，すなわち，変数が定義された時点からその定義が最後に使われるまでの期間，が重ならない２つの変数は同じレジスタに割り当てることができるという性質を利用する．

\subsection{レジスタ干渉グラフ}

レジスタ干渉グラフは，生存期間の重なりを無向グラフによって表現したものである．無向グラフの頂点に変数を割り当ててその生存期間が重なる場合には，その頂点間に辺をつける．互いに生存期間が重ならない変数については対応する頂点は辺を持たない．従って，$(u,v)\notin E$のとき，$u$に割り当てられた変数と$v$に割り当てられた変数は同じレジスタに割り当てることができる．

無向グラフに対する$k$-彩色問題とは，辺の両端にある頂点に違う色を割り当てるときに
$k$種類の色によって塗り分けが可能かどうかを判定する問題である．

\begin{Def}
    無向グラフ$(V,E)$に対する$k$-彩色問題とは，すべての辺$(u,v)\in E$に対して，$f(u)\not=f(v)$となる関数$f$:$V\rightarrow\{1,\ldots,k\}$が存在するとき，YES, 存在しないときNOと答える問題である．
\end{Def}

レジスタ干渉グラフを構成すると$k$彩色問題でYESとなる関数$f$は，レジスタ割り当てそのものである．グラフの彩色問題はNP完全な問題であり，一般に最適なレジスタ割り当てを求めることはコンパイラの構成として実際的ではない．

実際的なレジスタ割り当てを行うために以下の定理を利用することができる．

\begin{Thm}\label{thm:kindexGraph}
    無向グラフ$(V,E)$の任意の頂点の次数が$k-1$以下ならば$k$-彩色可能である．ここで，$k\geq 1$とする．
\end{Thm}

この定理を利用して，レジスタ干渉グラフに対する$k$-彩色アルゴリズム\ref{alg:graphColoring}を構成する．ここで，$G=(V,E)$において，$G\backslash\{v\}$は，頂点$v$を削除して，$v$を含む辺を削除して得られるグラフである．さらに，独立集合$I$に対して$G\backslash I$は，$I$に含まれる頂点をすべて削除し，$I$に含まれる頂点を含む辺をすべて削除して得られるグラフを表す．このアルゴリズムを呼び出すときには，集合$Spill$は空集合とする．

\begin{algorithm}
    \caption{レジスタ割り当ての彩色アルゴリズム}\label{alg:graphColoring}
    \begin{algorithmic}[1]
        \Procedure{$Color$}{$G$,$k$}
        \If{$G\not=\emptyset$}
        \If{$deg(v)\leq k-1$となる$v$が存在}
        \State $Color(G\backslash\{v\},k)$
        \State $v$に隣接した頂点と異なる割り当て可能な最小の色を割り当てる．
        \Else
        \State $v_r\leftarrow\bot$
        \For{each $v\in V$}
        \If{$v_r=\bot$}
        \State $v$に隣接している頂点集合の中から要素数最大の独立集合$I$を求める
        \If{$|I|\geq deg(v)-(k-2)$}
        \State $v_r\leftarrow v$
        \EndIf
        \EndIf
        \EndFor
        \If{$v_r\not=\bot$ かつ $k\geq 2$}
        \State $I$のすべての頂点に$k$番目の色を割り当てる
        \State $Color(G\backslash I,k-1)$
        \Else
        \State $v\in V$を一つ選んで$Spill$に追加
        \State $Color(G\backslash \{v\},k)$
        \EndIf
        \EndIf
        \Else\ 何もしない．
        \EndIf
        \EndProcedure
    \end{algorithmic}
\end{algorithm}

３行目の条件が成り立つときには，定理\ref{thm:kindexGraph}を利用する．6行目から，14行目で，隣接頂点集合の集合から独立集合の集合を求め，そのうちでの要素数最大のものを$I$とする．$I$は互いに辺で結ばれていないことが保証されるので，同じ色に塗ることができる．その大きさによって3行目と同様の条件が成り立つならば，彩色が可能である．そのような頂点が見つからなかった場合($v_r=\bot$)のときは，彩色を諦めてノードを一つ選んで$Spill$に登録し，削除した上で彩色を試みる．(18,19行目)

このアルゴリズムにおいて，定理\ref{thm:kindexGraph}の条件が成り立たない時，要素数最大の独立集合を求める必要がある．要素数最大の独立集合を求める問題はNP完全問題である．

このアルゴリズムは再帰呼び出しの際に必ず，$G$か$k$の一方が減少しているので必ず停止する．

彩色ができた場合に，各干渉グラフのノードが$i$番目の色に彩色されたとき，その変数にレジスタ$i$を割り当てる．

\subsection{SSAに対するレジスタ割当}

SSA形式からは，比較的容易にレジスタ割り当てを導く手法が知られている．SSA形式では，最適化後においても支配関係が保存されていることが仮定できるため，各変数の生存期間は新たな添字をもつ変数が定義されてから，次の添字を持つ変数が定義されるまでの間となる．各変数に対して生存期間に対応する頂点を抽出し，その頂点から構成される支配木の部分木を構成する．その部分木の交差グラフを構成するとレジスタ干渉グラフが構成でき，レジスタ干渉グラフは弦グラフとなる．弦グラフは，完全消去順序(PEO)に基づいて彩色することができる．

\subsubsection{弦グラフの彩色}

1章において，無向グラフの4以上の閉路に対して少なくとも１つの弦を持つグラフを{\bf 弦グラフ}として導入した．グラフ$G$の彩色数(Chromatic number)を$\chi(G)$，$\omega(G)$を$G$が含むクリーク(clique)の最大のサイズとする．

\begin{Prop}
弦グラフ$G$に対して$\chi(G)=\omega(G)$
\end{Prop}

弦グラフにおいては，部分グラフとして含むクリークの最大数で彩色が可能である\footnote{このような性質を持つグラフは一般に完全グラフ(perfect graph)と呼ばれる．}．弦グラフ$(V,E)$の頂点$V$に対しては，完全消去順序(PEO)が存在する．これは，弦グラフの頂点を取り除くとき，必ず部分グラフとしてクリークが存在するため，頂点を取り除いたとしてもFill-in辺を加える必要がないことを示している．

\begin{Exmp}

\begin{Prop}
無向弦グラフ$G=(V,E)$に対して$\chi(G)$は，$\mathcal{O}(|V|+|E|)$で求められる．
\end{Prop}

\subsubsection{SSA形式のレジスタ干渉グラフ}

以下ではレジスタ割り当てを考えるため，
フローグラフの各頂点として個々の命令
$y\leftarrow\tau(\tilde{x})$を考える．
ここで，$\tau$は演算，$\tilde{x}$は演算の引数となる変数である．
% 基本ブロックのフローを表す一つの命令
% \[(y_1,\ldots,y_m)\leftarrow\tau(x_1,\ldots,x_n)\]
% が割り当てられているとする．これは，基本ブロックに$x_1,\ldots,x_n$
% が流入して，$y_1,\ldots,y_m$という変数から出力されることを表す．
% SSAなので，$y_1,\ldots,y_m$はプログラム中ですべてユニークであり，
% $D_{y_i}$でこの基本ブロックを参照することにする．

% ここでは，$\varphi$関数の消去によって新たに加えられた代入については
% 元からあったブロックと結合せず，分離したブロックとして扱うことにする．

SSAにおいて，変数$v_i$が$D_{v_i}$で定義されると，
次の同じ変数に対する新たな定義$v_{i+1}$が定義されるまで生存する．

\begin{Prop}
SSAにおける変数$v$の生存範囲は，支配木における連結部分木である．
\end{Prop}

支配関係の定義から，ある変数$v$が参照されるノード$p$は$D_v$に支配される．
$D_v$から$p$に至るすべての支配木上のノードも$D_v$に支配されることから，
次に$v$が上書きされるまで連結した部分木として$v$は生存する．

干渉グラフは，各変数の生存が重複する可能性のある場合，すなわち，支配木における部分木の交差グラフ（１章において導入した）として構成される．

\begin{Lem}
    SSA形式から支配木の部分木から構成された交差グラフによる干渉グラフは弦グラフである．
\end{Lem}

\begin{proof}
$n\geq 4$である$n$個の変数の生存範囲を示す部分木$S_1$, $S_2,\cdots,S_n$があり，$S_i$と$S_{i+1}$ ($1\leq i< n$)および$S_1$と$S_n$が交差するとすると，干渉グラフでは，４以上の長さの閉路となる．
個々の部分木$S$のなかで最も根に近い頂点を$t(S)$と書くことにする．
$t(S_1),\ldots,t(S_n)$の中で最も支配木の根からのパスが遠いものを
$t(S_i)$とすると，$S_i$と交差する$S_j$と$S_k$は$t(S_i)$を共有するので，$S_j\cap S_k\not=\emptyset$となり，$S_j$と$S_k$の交差グラフには
辺が存在するため，4以上の閉路に必ず弦が存在する．
\end{proof}

一般のグラフ彩色問題がNP完全であることからすれば，SSA形式については$\chi(G)$よりも多くのレジスタがある場合にはそれほど時間がかからないことが示される．

以上のことから，SSAから構成される干渉グラフの大きさに対して線形時間で最小の色数で彩色できる．
ただし，最初から色数を指定して彩色する問題ではないため，レジスタ溢れについての問題を
解いたわけではないことに注意する．SSA形式からのレジスタ割り当ては，生存解析が容易になることによって効率的で最適な割り当て手法を与える．レジスタ数が少ない場合のレジスタ溢れの最適化問題(どの変数をメモリに待避させるか)は，依然，計算量の大きいNP完全問題として残るため，レジスタ割り当て問題全体としての計算複雑さが線形問題になるわけではない．

\subsubsection{$\varphi$関数の消去とレジスタ割当て}
